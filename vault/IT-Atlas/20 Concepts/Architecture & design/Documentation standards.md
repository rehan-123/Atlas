# Documentation standards

> [!abstract] In one line
> What good IT documentation contains so anyone on shift can support a client without asking around.

> [!tip] Think of it like
> A good recipe book: someone who's never cooked the dish can follow it and get the same result.

> [!info]+ Words on this page
> **IP**: Internet Protocol address: a device's address on the network, like 192.168.1.20.
> **ISP**: Internet service provider.
> *More in the [[Glossary]].*

## How it works

- Per client: network diagram, IP plan, ISP and vendor contacts, credentials in the password vault, backup design, critical apps and their owners.
- Runbooks for recurring tasks; known issues and their fixes.
- Every page has an owner and a last-reviewed date.
- Documentation is part of the change: no change is finished until the docs match.
